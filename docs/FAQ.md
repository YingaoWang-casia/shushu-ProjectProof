# FAQ

## 1. 这个 Skill 会帮我“包装”成没做过的经历吗？

不会。这个项目的核心边界是“真实信息 + 证据约束”。  
它会帮你降级风险表达、补工程化证据、提升可讲性，但不会鼓励虚构上线、虚构指标或虚构个人贡献。

## 2. 我只有很普通的小项目，真的有用吗？

有用。大多数项目被否定，不是因为“太小”，而是因为“讲不清”。  
这个 Skill 的重点是把小项目讲清楚：输入输出、角色边界、bad case、评估口径和工程约束。

## 3. 我没有完整 JD，还能用吗？

能用。先给目标岗位方向（例如“后端实习”“大模型应用实习”），Skill 会先按通用能力框架诊断，再提示你需要补哪些 JD 信息。

## 4. 我没有指标数据，会不会没法写？

可以写，但要降级。  
比如把“提升准确率 30%”降成“基于样例集观察到稳定改进趋势，并沉淀 bad case 与回归流程”。  
先保证真实，再补证据升级表达。

## 5. `references` 里为什么有很多 `TODO`？

这是模板占位符，不是文档未完成。  
`TODO` 表示“由用户真实项目内容替换”的填写槽位。

## 6. 我应该先改简历还是先练面试？

建议顺序：

1. 先做真实性边界和 Evidence Contract。  
2. 再改简历 bullet。  
3. 最后做追问树和 mock interview。  

这样能避免“简历写得很强，但一问就崩”。

## 7. 怎么判断我现在是否可投递？

看这三个信号：

1. 是否能清楚说出“我做了什么/没做什么”。  
2. 是否有至少 3 条可复述的 bad case。  
3. 是否对“结果表达”有证据口径。  

满足前两条通常可投；三条都满足，面试稳定性会明显更高。

## 8. 开源贡献最有价值的是哪些内容？

优先级最高：

1. 真实脱敏 eval case。  
2. 某岗位的高频追问分支。  
3. 危险表达到安全表达的 before/after。  
4. 可复用的证据清单模板。
