# Demo Output（脱敏示例）

目标：展示这个 Skill 在真实风格输入下，如何输出“可投递、可讲述、可追问防守”的结构化结果。

## 输入（节选）

```text
目标岗位/JD：
大模型应用开发实习生，要求熟悉 RAG、Agent、工具调用、Prompt 优化、评估体系和工程化落地。

简历原文：
参与公司智能体项目，负责 prompt 优化和知识库问答效果优化，提升回答准确率。

真实情况：
1) 项目是内部 demo，没有线上正式发布。
2) 我负责历史问答样例整理、Prompt 模板维护、文档切分和向量入库流程联调。
3) 底层模型与向量库由同事搭建，我没有训练模型。
4) 记录过 bad case：幻觉、引用错位、表格召回失败、JSON 字段缺失。
5) 没有完整 AB 数据，只有若干前后对比样例和日志截图。
```

### 5) Toy 感与漏洞诊断（按严重程度）

1. 高危：把“内部 demo”写成“业务落地”。
2. 高危：把“局部样例变好”写成“准确率提升”。
3. 中危：贡献边界不清，容易被质疑“只是调 API”。
4. 中危：没有展示失败处理机制（重试、校验、兜底）。
5. 可优化：缺少版本化与复盘材料（Prompt 版本、case 归档）。

### 8) Upgrade Plan

半天：
- 整理 20 条 bad case，按“触发条件-错误表现-处理动作”分类。
- 产出贡献边界说明：我做/同事做/平台做。

1 天：
- 建一个最小评估集（50 条问答）。
- 定义两个指标：citation accuracy、answer relevance（人工标注口径）。

3 天：
- 为链路补 `trace_id`、节点耗时和失败原因日志。
- 增加结构化输出校验和单次重试策略。

1 周：
- 做一次完整回归：版本 A/B 的 bad case 对比和改进报告。
- 输出可演示的“从输入到证据引用”的链路说明文档。
