# End-to-End Cases

完整案例用于把 Skill 从资料库变成可复用教练。每个案例都展示：原始简历、诊断、追问、补强、改写、面试防线。

## Case 1：小厂 Agent 只调 API

### 原始描述

```text
参与公司智能客服 Agent 项目，负责 prompt 优化和数据清洗。
```

### 诊断

- 业务场景模糊：不知道客服处理什么问题。
- 技术深度弱：像 prompt + API。
- 没有工具调用、状态管理、权限、人工复核。
- 没有 bad case 和评估口径。

### 必问问题

1. Agent 是否调用工具？工具输入输出是什么？
2. 用户问题来自哪里？历史客服数据还是实时输入？
3. 输出是直接给客户，还是给客服审核？
4. 出过哪些错误回答？
5. 有没有日志记录 query、prompt、工具、结果？

### 可补强

半天：整理 10 条错误回答，分类为幻觉、字段缺失、格式错误、工具失败。  
1 天：给输出加 JSON schema 和失败重试。  
3 天：加 trace_id 日志和人工复核状态。  
1 周：构造 50 条任务评估集，统计任务成功率和人工复核通过率。

### 改写

保守版：

```text
参与内部客服 Agent 原型开发，负责历史问答数据整理、Prompt 模板维护和输出样例分析；梳理模型幻觉、字段缺失和格式不一致等 bad case，为后续工程化改造提供依据。
```

标准版：

```text
参与内部客服 Agent 工具开发，负责输入数据清洗、结构化输出校验和 trace 日志记录；针对模型幻觉、字段缺失、工具调用失败等 bad case 补充规则校验、失败重试和人工复核流程。
```

### 面试防线

```text
这个项目不是模型训练项目，我的重点是 LLM 应用工程化。小厂阶段主要验证业务链路，但我复盘后补齐了工具调用参数校验、输出 schema、bad case 回归和人工复核设计，能说明我理解 Agent 从 demo 到可用流程的关键差距。
```

## Case 2：文档 RAG 没考虑表格和跨页

### 原始描述

```text
参与企业知识库问答系统，负责文档向量化和问答效果优化。
```

### 诊断

- “效果优化”没有证据。
- 文档解析细节缺失：表格、跨页、目录、页眉页脚。
- 引用和权限缺失。
- 没有 query-answer-evidence 评估集。

### 必问问题

1. 文档类型是 PDF、Word、Excel 还是网页？
2. 表格怎么解析？跨页表格怎么办？
3. chunk 是否保留 page、section、table_id？
4. 问答引用是否能定位到页码/段落？
5. 有没有无答案拒答？

### 可补强

半天：整理 8 条文档解析 bad case。  
1 天：给 chunk metadata 增加 doc_id、page、section、version。  
3 天：做 30 条 query-answer-evidence 评估集。  
1 周：对比纯向量、BM25、混合检索和 rerank。

### 改写

```text
参与内部文档 RAG 工具开发，负责文档预处理、chunk 策略和生成结果引用校验；针对表格召回不准、跨页上下文缺失、页眉页脚污染和无依据回答等 bad case，补充 metadata、引用校验和拒答策略。
```

### 面试防线

```text
当时项目更偏 demo，没有完整处理复杂版面。现在复盘，我会把文档解析单独作为一层，区分正文、表格、目录、页眉页脚和扫描件，对 chunk 保留 page、section、table_id 等 metadata，并用 query-answer-evidence 评估召回和引用准确性。
```

## Case 3：小厂算法实习只有数据清洗

### 原始描述

```text
负责业务数据清洗，支持算法模型训练。
```

### 诊断

- 容易被认为是整理 Excel。
- 没有字段、规则、质量报告。
- 没有说明对模型训练的影响。
- 没有个人贡献边界。

### 必问问题

1. 原始数据有哪些字段？
2. 缺失、重复、异常值分别怎么处理？
3. 标签从哪里来？有没有噪声？
4. 清洗后如何验证？
5. 下游模型如何使用这份数据？

### 可补强

半天：补字段字典和清洗规则表。  
1 天：输出数据质量报告，统计缺失率、重复数、异常样例。  
3 天：做抽样人工复核和错误类型分类。  
1 周：把清洗流程 pipeline 化，加 schema check 和 smoke test。

### 改写

```text
负责原始业务数据到可评估数据集的处理流程，设计字段标准化、缺失/重复/异常样本处理和抽样复核规则；输出数据质量报告和错误样例，为后续模型训练和指标评估提供可信数据基础。
```

## Case 4：推荐/搜索实验指标弱

### 原始描述

```text
参与推荐算法优化，提升推荐准确率。
```

### 诊断

- “准确率”不一定适合推荐。
- 不知道召回/排序层级。
- 没有 baseline 和指标口径。
- 没有线上验证。

### 必问问题

1. 你做的是召回、粗排、精排还是重排？
2. baseline 是规则、协同过滤、双塔还是已有模型？
3. 指标是 Recall@K、NDCG、MAP、CTR 还是转化？
4. 数据如何按时间切分？
5. 冷启动和长尾样本怎么处理？

### 可补强

半天：明确推荐链路位置和指标。  
1 天：补 baseline vs 改进方案表。  
3 天：做分层评估：新用户、老用户、长尾 item。  
1 周：设计线上 AB/灰度和特征监控方案。

### 改写

```text
围绕 TODO 推荐/搜索任务搭建离线评估流程，负责样本构造、特征处理和 baseline 对比；通过 Recall@K/NDCG 等指标分析不同用户分层和长尾样本表现，定位离线指标与业务目标不一致的风险。
```

## Case 5：语音 API 项目

### 原始描述

```text
参与语音识别项目，负责接口调用和结果测试。
```

### 诊断

- 不像语音算法，更像 API 接入。
- 缺少音频格式、采样率、VAD、WER/CER。
- 没有噪声、口音、重叠说话 bad case。

### 必问问题

1. 音频采样率、格式、时长是什么？
2. 是否有 VAD？是否会截断？
3. WER/CER 怎么统计？
4. 噪声和口音样例效果如何？
5. 接口超时或失败怎么处理？

### 可补强

半天：整理音频 bad case。  
1 天：统计 20 条样例 CER/WER。  
3 天：补 VAD/重采样/格式校验。  
1 周：做流式延迟统计和质量报告。

### 改写

```text
参与语音识别工具开发，负责音频格式校验、识别结果测试和 bad case 分析；围绕噪声、口音、静音截断和采样率不一致等问题构建小型评估样例，统计 CER/WER 和接口延迟，为后续语音链路优化提供依据。
```
