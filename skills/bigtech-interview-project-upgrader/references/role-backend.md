# Role: 后端开发 / Java / Go / Python

适用：Java 后端、Python 后端、Go 后端、微服务、业务系统、内部平台、接口开发。

## 大厂看重点

- 能讲清接口、数据库、缓存、消息队列、事务、幂等、权限、稳定性。
- 不只是 CRUD，要体现业务状态流、异常处理、性能和工程规范。
- 能解释技术取舍：为什么这样拆表、为什么加缓存、为什么异步、为什么要事务。

## Toy 感

- 只写“完成增删改查接口”。
- 没有数据库设计、索引、事务、权限、错误码。
- 没有并发、幂等、重复提交、缓存一致性处理。
- 没有日志、测试、部署、接口文档。
- 没有真实业务流程，只像后台模板。

## 可补强动作

半天：

- 补接口文档：请求、响应、错误码、权限。
- 补核心表结构和状态流。
- 整理 5 个异常场景：参数错、重复提交、权限不足、数据不存在、状态不允许。

1 天：

- 增加参数校验、统一错误返回、操作日志。
- 补一个事务边界或幂等设计。
- 补 3-5 个单测/接口测试。

3 天：

- 加 Redis 缓存或本地缓存，并说明一致性策略。
- 加异步任务/消息队列处理耗时操作。
- 做简单压测和慢查询分析。

1 周：

- 做权限模型、审计日志、限流、监控告警。
- 做 Docker Compose 一键启动。
- 补 CI、数据库迁移、集成测试。

## 简历表达素材

保守版：

```text
参与内部业务系统后端开发，负责 TODO 模块的接口实现、参数校验和数据库表维护；补充接口文档和异常场景说明，支持前端联调和业务流程验证。
```

标准版：

```text
参与 TODO 业务系统后端开发，负责核心接口、数据库表设计和状态流处理；针对重复提交、权限校验和异常状态补充幂等校验、统一错误码和操作日志，提升接口可维护性和问题定位效率。
```

偏强版：

```text
负责 TODO 模块从接口设计到联调上线的闭环，设计数据库状态流、事务边界和幂等策略；通过缓存/异步任务/索引优化处理 TODO 性能或一致性问题，并补充接口测试、审计日志和部署文档。
```

## 高频追问

1. 数据库表怎么设计？为什么这样拆？
2. 哪些操作需要事务？事务隔离级别了解吗？
3. 重复提交怎么处理？
4. 接口幂等怎么做？
5. 缓存怎么用？缓存一致性怎么保证？
6. 慢查询怎么定位？
7. 权限模型怎么设计？
8. 线上报错怎么排查？
9. QPS 变高怎么办？
10. 如果服务拆成微服务，边界怎么划？

## 回答防线

- 没有高并发别硬写高并发，可以写“补了幂等/缓存/压测方案”。
- 没上线别说生产稳定性，可以说“补了部署文档、smoke test 和日志定位路径”。
- CRUD 项目要靠状态流、异常、权限、测试和数据一致性拉开差距。
