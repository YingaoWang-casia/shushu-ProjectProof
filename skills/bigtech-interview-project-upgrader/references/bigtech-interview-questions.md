# Big-Tech Interview Questions

用于模拟大厂项目深挖。按强度分层。

## 一面：项目真实性和基础实现

1. 这个项目解决什么真实问题？为什么需要做？
2. 你负责哪些模块？哪些不是你做的？
3. 输入是什么，输出是什么？关键字段有哪些？
4. 核心链路从入口到结果怎么走？
5. 你遇到的最大 bug 或 bad case 是什么？
6. 你怎么验证功能正确？
7. 项目有没有上线？没有的话完整跑到哪一步？
8. 如果让我看代码，你会先带我看哪几个文件？

## 二面：设计、取舍和扩展

1. 为什么用这个方案？备选方案是什么？
2. 数据量/流量/调用量变大 10 倍怎么办？
3. 如何保证稳定性、可观测性和可回滚？
4. 哪些地方最容易出错？怎么兜底？
5. 如果重构，你会先重构哪里？
6. 你如何设计测试体系？
7. 这个项目的瓶颈在哪里？
8. 安全、权限、隐私和成本怎么考虑？

## 主管面：ownership 和成长性

1. 这件事是不是你主动发现并推动的？
2. 项目里最体现你个人价值的部分是什么？
3. 如果没有你，项目会有什么不同？
4. 你怎么和产品、运营、同事沟通需求？
5. 你有没有推动流程改善、文档沉淀或规范沉淀？
6. 这段经历说明你适合我们团队的什么工作？

## 高压追问

1. 你这个项目听起来很简单，难点到底在哪里？
2. 你说提升效率，数据从哪来？
3. 你说负责模块，为什么不是同事做的？
4. 你说 Agent，和普通 chatbot 有什么区别？
5. 你说算法优化，为什么指标提升可信？
6. 你说上线，谁在用？用了多久？失败过吗？
7. 你说高并发，QPS 多少？压测怎么做的？
8. 你说工程化，日志、监控、告警、回滚在哪里？

## 回答模板

推荐顺序：

```text
先承认边界 -> 再讲真实职责 -> 再讲技术动作 -> 再讲证据 -> 最后讲局限和后续
```

不要硬撑。大厂面试更怕“编”，不怕项目小。
