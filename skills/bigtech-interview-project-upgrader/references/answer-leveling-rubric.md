# Answer Leveling Rubric

目标：每个面试问题都要给出“危险/可过/强”三档答案，帮助用户知道自己现在处在哪一层。

## 一、三档标准

| 档位 | 特征 | 面试结果 |
| --- | --- | --- |
| 危险回答 | 空泛、夸大、无证据、不能承认边界 | 容易被追问穿 |
| 可过回答 | 能解释基本链路，但缺少指标和复盘 | 普通通过 |
| 强回答 | 有业务背景、技术取舍、bad case、证据和边界 | 有高面评信号 |

## 二、通用回答结构

强回答尽量包含：

```text
背景/目标
我负责的边界
核心链路
关键难点
bad case
怎么验证
限制和后续
```

## 三、典型问题分层

### Q：这是不是只是调 API？

危险回答：

```text
不是，我们用了大模型，所以比较智能。
```

可过回答：

```text
底层模型确实是调用 API，我主要做 Prompt 和流程接入。
```

强回答：

```text
这个项目不是模型训练项目，底层能力来自模型 API。我的工作重点是 LLM 应用工程化：把业务输入清洗、Prompt 模板、工具调用、结构化输出、失败重试和人工复核串成可追踪流程。难点不是“调通 API”，而是让模型输出能稳定进入业务链路，并能通过 bad case 和日志定位问题。
```

### Q：RAG 效果怎么评估？

危险回答：

```text
我们看回答感觉还可以。
```

可过回答：

```text
人工抽了一些问题，看回答是否正确。
```

强回答：

```text
我会构造 query-answer-evidence 评估集，标注标准答案、证据页和问题类型，分别统计 topK 召回命中、答案正确性、引用准确率、无答案拒答准确率、延迟和成本。这样能区分是切分问题、召回问题、rerank 问题，还是生成阶段幻觉。
```

### Q：为什么加 rerank？

危险回答：

```text
因为 rerank 效果更好。
```

可过回答：

```text
向量召回结果有时不够准，rerank 可以重新排序。
```

强回答：

```text
向量召回适合语义相似，但在数字、条款、专有名词、表格字段上容易召回相似但不支持答案的 chunk。rerank 可以对 query 和候选 chunk 做更细粒度相关性判断。我不会直接说它一定提升，而是用评估集对比 rerank 前后的 evidence hit rate、citation accuracy 和延迟成本。
```

### Q：你们没上线，简历为什么写业务价值？

危险回答：

```text
虽然没上线，但功能都完成了。
```

可过回答：

```text
项目是内部验证阶段，所以我不会写线上效果。
```

强回答：

```text
这个项目没有公开线上运行，所以我不会写线上收益。能安全写的是：完成了内部业务流程验证，沉淀了文档解析、检索、生成和人工修订的链路；如果要证明价值，我会补离线样例集、人工复核记录和节点耗时数据，而不是虚构线上指标。
```

### Q：如果文档有跨页表格怎么办？

危险回答：

```text
直接转成文本应该也可以。
```

可过回答：

```text
需要单独处理表格和页码。
```

强回答：

```text
跨页表格不能简单按页切。需要识别 table_id、caption、header 和起止页，第二页表格要关联或复制表头，单元格要保留单位和原始字符串。检索时表格可用 Markdown/JSON 语义化文本，同时对精确数值查询结合关键词或结构化检索，避免向量召回把数字孤立化。
```

### Q：离线指标涨了，线上业务反而下降怎么办？

危险回答：

```text
可能是线上环境问题。
```

可过回答：

```text
离线和线上分布可能不一致，需要分析样本。
```

强回答：

```text
先不能假设模型一定有效。我会检查离线样本和线上流量分布、标签延迟、特征线上线下一致性、是否只提升头部样本、是否优化了错误指标。处理上先回滚或灰度，再分层看新老用户、场景、时间段和长尾样本，最后把线上失败样例回流到评估集。
```

## 四、输出要求

模拟面试时，每个关键问题至少给：

```text
危险回答：
可过回答：
强回答：
你的当前回答更像哪一档：
需要补的证据：
```
