# Role: 数据工程 / 数据治理 / ETL

适用：数据清洗、ETL、数仓、数据质量、数据同步、指标看板、业务分析。

## 大厂看重点

- 能讲清数据源、schema、清洗规则、调度、质量校验、对账和下游消费。
- 不是“整理 Excel”，而是规则化、可复现、可验证的数据处理流程。
- 能处理上游变更、重复消费、延迟、缺失、异常值和质量报告。

## Toy 感

- 只写“负责数据清洗”。
- 没有数据源、字段、规则、质量指标。
- 没有调度、日志、失败重试、对账。
- 没有下游使用场景。

## 可补强动作

半天：

- 写出数据源、字段、输出表、下游用户。
- 整理缺失、重复、格式不统一、异常值样例。
- 写清每条清洗规则。

1 天：

- 输出数据质量报告：行数、缺失率、重复数、异常样例。
- 增加 schema 检测和异常导出。
- 补清洗前后对比。

3 天：

- 把规则配置化，补单测。
- 加调度日志、失败重试、对账脚本。
- 做指标看板或导出报表。

1 周：

- 增加增量同步、幂等、血缘和质量告警。
- 设计数仓分层：ODS/DWD/DWS/ADS。
- 形成数据治理规范和字段字典。

## 简历表达素材

```text
负责 TODO 业务数据清洗流程，针对字段缺失、格式不一致、重复记录和异常值设计规则化处理逻辑；输出数据质量报告和异常样例清单，支持后续业务分析与人工复核。
```

```text
参与 TODO 数据同步/ETL 流程建设，负责 schema 校验、清洗规则配置和对账逻辑；通过日志、质量报告和异常导出提升数据处理可追踪性，降低上游数据变更导致的静默错误风险。
```

## 高频追问

1. 数据源是什么？字段有哪些？
2. 清洗规则怎么定义？写死还是配置化？
3. 如何处理缺失、重复、异常值？
4. 如何保证清洗结果正确？
5. 上游 schema 变了怎么办？
6. 失败重跑怎么避免重复写入？
7. 调度和日志怎么做？
8. 下游如何使用这些数据？
