# Truth Boundary

目标：帮助用户把真实经历讲强，但不跨越事实边界。

## 表达边界表

| 真实情况 | 可以写 | 不建议写 |
| --- | --- | --- |
| 做过 demo | 实现原型、验证流程、完成 demo | 上线生产系统 |
| 内部试用 | 支持内部试用、沉淀反馈 | 服务大量外部用户 |
| 参与协作 | 参与、协助、负责某模块 | 独立负责、主导整体 |
| 接入 LLM API | 接入模型 API、设计调用链路、约束输出 | 训练大模型 |
| 做 prompt | 维护 prompt 模板、整理 bad case | 独立设计完整 Agent 架构，除非有证据 |
| 做数据清洗 | 设计规则、处理缺失/重复/异常、输出质量报告 | 海量数据治理，除非规模真实 |
| 没有指标 | 写工程产出、验证方法、抽样结果 | 写具体提升百分比 |
| 小规模数据 | 内部业务数据、样本数据、抽样验证 | 大规模/海量数据 |
| 看过代码但没改 | 阅读核心链路、参与方案讨论 | 负责核心模块开发 |
| 计划补做 | 下一步计划、可扩展方向 | 已完成、已落地 |

## 四类内容

- 明确做过：可以写进简历，用“负责/实现/设计/优化”。
- 参与但非主责：可以写“参与/协助/对接”，面试时说明边界。
- 可以补做后再写：先列为升级计划，完成后再写成完成态。
- 不建议写：无证据的规模、指标、上线、主导、核心算法、生产事故。

## 面试守线话术

### 只是调 API 吗？

可以回答：这个项目不是模型训练项目，我的定位是应用工程化。重点在业务输入处理、调用链路、结构化输出、异常处理、日志、评估和人工复核，解决的是模型如何稳定接入真实业务流程。

### 有没有上线？

按真实状态回答：生产、内部试用、demo、原型、本地跑通。不要跨级表达。可以补充已有证据：截图、日志、运行命令、用户反馈、日报。

### 你的贡献在哪里？

用模块、接口、字段、规则、实验、日志、测试或文档证明，不要只说“参与项目开发”。

### 没有指标怎么办？

用抽样检查、质量报告、bad case 表、接口测试、日志统计、smoke test、人工对账替代空泛结果。
