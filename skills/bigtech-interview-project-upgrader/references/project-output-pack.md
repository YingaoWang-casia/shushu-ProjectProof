# Project Output Pack

目标：把诊断结果落成用户能投递、能背、能面、能补的交付物。不要只给建议。

## 一、最终交付清单

信息足够时，输出以下 8 件套：

1. **JD 匹配表**：岗位能力项、简历证据、缺口和策略。
2. **真实性边界表**：做过、参与、补做后可写、不能写。
3. **简历 Bullet 三档**：保守版、标准版、偏强版。
4. **2-3 分钟项目口述稿**：背景、目标、职责、方案、难点、结果、局限。
5. **架构/链路讲解稿**：输入、处理节点、输出、失败和监控。
6. **高频追问 20 题**：项目、八股、场景、高压质疑混合。
7. **回答分层卡**：危险/可过/强回答。
8. **补证据 Checklist**：半天、1 天、3 天、1 周。

## 二、简历版本要求

### 保守版

当前证据就能写。少用“优化”“提升”“落地”，多用“参与”“负责模块”“梳理”“支持”。

### 标准版

补少量证据后能写，例如 bad case 表、日志字段、评估样例、链路图。

### 偏强版

只有完成真实补做后才能写。必须附：

```text
不能现在直接写的原因：
补完需要什么证据：
面试如何证明：
```

## 三、2-3 分钟项目口述稿模板

```text
这个项目的背景是……
业务上要解决的问题是……
我负责的是……
整体链路可以拆成……
我遇到的主要难点是……
一个典型 bad case 是……
我当时/复盘后采用的处理方式是……
目前结果/证据是……
这个项目的边界是……
如果放到大厂生产环境，我会继续补……
```

## 四、架构讲解稿模板

```text
输入：
核心节点：
状态流转：
失败类型：
日志和 trace：
评估方式：
权限和安全：
性能与成本：
```

## 五、高频追问组合

每个输出包必须包含：

- 5 个真实性问题。
- 5 个链路细节问题。
- 4 个八股转场问题。
- 4 个生产场景题。
- 2 个高压质疑题。

## 六、投递前质量门

最终交付前检查：

- 有没有无证据指标。
- 有没有把参与写成主导。
- 有没有把 demo 写成生产。
- 有没有把 API 接入写成模型训练。
- 有没有至少 5 个 bad case。
- 有没有至少 3 个可展示证据。
- 能否把项目讲到输入、输出、异常、指标和取舍。

如果任一质量门不通过，输出：

```text
当前不建议写偏强版。
原因：
先补：
保守版可用表达：
```
