# Role: 语音 / 音频算法 / ASR / TTS

适用：语音识别、语音合成、唤醒、VAD、降噪、音频处理、多模态音频、实时语音应用。

## 大厂看重点

- 能讲清语音任务定义：ASR、TTS、VAD、KWS、降噪、说话人识别。
- 能讲清数据：采样率、时长、标注、噪声、口音、切分、增强。
- 能讲清指标：WER/CER、RTF、延迟、MOS、准确率、召回率、误唤醒率。
- 能处理真实 bad case：噪声、口音、重叠说话、远场、截断、延迟。

## Toy 感

- 只跑开源 demo，没有数据和指标。
- 只说“调用语音 API”，没有音频预处理。
- 没有采样率、格式、切片、VAD、延迟说明。
- 没有噪声/口音/实时性 bad case。
- 把调 API 说成训练 ASR/TTS 模型。

## 可补强动作

半天：

- 整理音频输入输出：采样率、格式、时长、声道、场景。
- 整理 10 条 bad case：噪声、口音、快语速、静音、截断、重叠说话。
- 写出处理链路：音频读取 -> 预处理 -> VAD/特征 -> 模型/API -> 后处理 -> 输出。

1 天：

- 增加音频格式校验和重采样。
- 加 VAD 或静音过滤。
- 记录延迟、音频长度、错误类型。

3 天：

- 做小型评估集，统计 CER/WER 或任务准确率。
- 对比不同噪声增强、阈值、chunk size、模型/API 参数。
- 做流式延迟测量。

1 周：

- 增加实时流式处理、缓存、队列或并发处理。
- 做音频 bad case 可视化：波形、频谱、识别结果、错误标注。
- 增加质量报告和回归集。

## 回答防线

- 没训练模型就说清是“语音 API/开源模型应用 + 预处理/评估/后处理”。
- 没有大规模数据时，强调 bad case 集、评估方法和真实音频问题。
