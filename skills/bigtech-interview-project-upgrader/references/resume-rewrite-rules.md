# Resume Rewrite Rules

目标：把真实项目写得更专业、更贴 JD、更抗面试深挖。

## Bullet 公式

推荐结构：

```text
业务场景 + 个人职责 + 技术动作 + 难点/约束 + 结果/证据
```

示例：

```text
参与内部客服 Agent 工具开发，负责历史问答数据清洗、Prompt 模板维护和结构化输出校验；针对字段缺失、格式不一致和工具调用失败等 bad case 补充规则校验、失败重试和人工复核流程，提升问题定位和后续迭代效率。
```

## 三档输出

### 保守版

适合证据较少或项目未上线时：

```text
参与 TODO 项目，负责 TODO 模块，完成 TODO 功能/文档/数据处理，并整理 TODO 问题样例和后续优化方向。
```

### 标准版

适合已有代码、demo、内部试用或明确职责时：

```text
参与 TODO 业务场景下的 TODO 系统开发，负责 TODO 模块；围绕 TODO 难点补充 TODO 工程动作，产出 TODO 结果/证据。
```

### 偏强版

必须有证据支撑：

```text
负责 TODO 从原型到内部试用/可演示闭环的改造，设计 TODO 方案解决 TODO 问题；通过 TODO 指标/日志/评估/测试验证效果，并沉淀 TODO 规范/工具/流程。
```

## 禁用空话

少用：

- 熟悉、了解、参与相关工作。
- 提升系统稳定性，优化用户体验。
- 负责项目开发，完成领导安排。
- 使用 AI 技术提升效率。

改成：

- 处理了哪些输入输出。
- 负责了哪个模块或链路。
- 解决了哪类失败样例。
- 通过什么证据验证。
- 有哪些限制和后续计划。

## JD 对齐

每条 bullet 至少命中一个 JD 关键词：

- 后端：高并发、缓存、数据库、微服务、接口设计、稳定性。
- 前端：组件化、性能、状态管理、工程化、可视化、体验。
- 大模型/Agent：RAG、工具调用、prompt、评估、对齐、输出校验。
- 算法：特征、模型、指标、实验、线上/离线一致性。
- 语音：ASR、TTS、VAD、降噪、延迟、WER、实时性。

## 结尾检查

- 这条 bullet 面试官能追问出具体细节吗？
- 你能讲出对应代码/文档/日志/实验吗？
- 有没有越界表达？
- 是否比原文更短、更硬、更贴岗位？
