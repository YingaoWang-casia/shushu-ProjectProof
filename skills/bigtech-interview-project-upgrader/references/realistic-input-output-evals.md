# Realistic Input/Output Evals

这个文件用于评测 Skill 是否真的像产品，而不是只会泛泛建议。每个 eval 给出用户可能输入的烂简历片段，以及 Skill 必须命中的诊断点、追问点、降级表达和补强动作。

## Eval 1：小厂 Agent，只写 Prompt 优化

### 输入

```text
目标岗位：剪映 AIGC/Agent 实习
简历：参与公司智能客服 Agent 项目，负责 prompt 优化和数据清洗，提升回答准确率。
真实情况：主要是调用大模型 API，整理了一些问答样例，没有上线。
```

### 必须诊断

- “提升回答准确率”没有指标口径，必须降级。
- 不能写 Agent 建设经验很强，只能写 LLM 应用原型/Agent 原型。
- 缺少工具调用、状态管理、结构化输出、日志、人工复核。
- 缺少 bad case 和评估集。
- 与剪映 JD 的匹配点应转成：Prompt、AI 生成链路、Agent 流程编排、评估与落地。

### 必须追问

1. Agent 是否调用工具？有哪些工具？
2. 输出是否直接给用户，还是人工审核？
3. 有哪些错误回答？
4. 准确率如何统计？
5. 有没有 trace 日志和 prompt 版本？

### 安全表达

```text
参与内部 Agent 原型开发，负责历史问答样例整理、Prompt 模板维护和输出 bad case 分析；针对模型幻觉、格式不一致和字段缺失等问题梳理规则校验、失败重试和人工复核方案，为后续工程化改造提供依据。
```

## Eval 2：文档 RAG，没考虑表格跨页

### 输入

```text
目标岗位：AIGC/RAG/MCP
简历：参与知识库问答项目，负责文档向量化和 RAG 效果优化。
真实情况：把 PDF 转文本后切 chunk，存向量库，能问答，没有专门评估。
```

### 必须诊断

- “效果优化”无证据，必须降级。
- 必须追问文档解析：表格、跨页、页眉页脚、目录、扫描件。
- 必须追问引用：是否能定位到 page/section/chunk。
- 必须追问评估集：query-answer-evidence。
- 必须追问权限和增量索引。

### 必须追问

1. PDF 是文本型还是扫描件？
2. 表格如何保留表头和单位？
3. 跨页段落如何 merge？
4. 只用向量召回吗？编号/数字怎么召回？
5. 如何统计 retrieval hit rate 和 citation accuracy？

### 安全表达

```text
参与内部文档 RAG 工具开发，负责文档预处理、chunk 策略和问答样例分析；针对表格召回不准、跨页上下文缺失、页眉页脚污染和无依据回答等问题整理 bad case，并补充 metadata、引用校验和拒答策略设计。
```

## Eval 3：数据清洗被写成算法优化

### 输入

```text
目标岗位：算法/AIGC 实习
简历：负责业务算法优化，提升模型效果。
真实情况：主要做数据清洗，处理字段缺失、重复和异常值。
```

### 必须诊断

- 不能写“算法优化”，除非有模型实验和指标。
- 可以包装成“算法数据闭环/数据质量”。
- 必须追问数据字段、标签来源、清洗规则、质量报告、下游模型使用。

### 必须追问

1. 原始数据字段有哪些？
2. 缺失/重复/异常值比例是多少？
3. 清洗前后如何验证？
4. 下游模型使用这些数据做什么？
5. 有没有质量报告或抽样复核？

### 安全表达

```text
负责业务数据到可评估数据集的处理流程，设计字段标准化、缺失/重复/异常样本处理和抽样复核规则；输出数据质量报告和错误样例，为后续模型训练与指标评估提供可信数据基础。
```

## Eval 4：推荐实验只写准确率提升

### 输入

```text
目标岗位：推荐/算法实习
简历：参与推荐算法优化，准确率提升 15%。
真实情况：跑了一个分类模型，数据随机划分，没有线上实验。
```

### 必须诊断

- “准确率提升 15%”高危：指标不适合推荐，且无口径。
- 必须追问推荐链路层级：召回/粗排/精排/重排。
- 必须追问 NDCG/Recall@K/MAP/CTR。
- 必须追问数据泄漏和随机划分风险。

### 必须追问

1. 这个模型在哪一层？
2. baseline 是什么？
3. 数据按时间还是随机切分？
4. 是否同一用户穿越训练/测试？
5. 线上 CTR 不涨怎么办？

### 安全表达

```text
围绕推荐排序任务搭建离线评估流程，负责样本构造、特征处理和 baseline 对比；通过 Recall@K/NDCG 等指标分析不同用户分层和长尾样本表现，并梳理离线指标与线上业务目标不一致的风险。
```

## Eval 5：语音 API 项目写成语音算法

### 输入

```text
目标岗位：语音/多模态 AI
简历：参与语音识别算法项目，优化识别效果。
真实情况：调用第三方 ASR API，做了一些测试。
```

### 必须诊断

- 不能写“语音识别算法优化”，应写语音 API 应用/评估/工程。
- 必须追问采样率、音频格式、VAD、WER/CER、噪声和口音 bad case。

### 必须追问

1. 音频采样率和格式是什么？
2. 有没有 VAD？是否截断？
3. WER/CER 如何统计？
4. 噪声、口音、重叠说话表现如何？
5. 接口超时如何处理？

### 安全表达

```text
参与语音识别工具开发，负责音频格式校验、识别结果测试和 bad case 分析；围绕噪声、口音、静音截断和采样率不一致等问题构建小型评估样例，统计 CER/WER 和接口延迟。
```

## Eval 6：MCP 只听过没做过

### 输入

```text
目标岗位：剪映 AIGC/MCP
简历：熟悉 MCP 协议和 Agent 工具调用链路。
真实情况：只看过一些资料，没有实际做过 MCP。
```

### 必须诊断

- 不能写“熟悉 MCP 协议”，最多写“了解 MCP 基本概念”。
- 必须建议补做一个最小 MCP demo，完成后才能写。
- 必须把能力转向：工具 schema、权限、trace、重试、human-in-the-loop。

### 必须追问

1. 是否实现过 MCP server/client？
2. 工具有哪些 schema？
3. 工具调用失败如何处理？
4. 权限和安全边界如何设？

### 安全表达

```text
了解 MCP 协议在 Agent 工具调用中的基本思路，能够结合工具 schema、权限控制、调用日志和失败重试设计 Agent 工具链路；计划补充最小 MCP demo 以验证端到端调用流程。
```

## Eval 7：多模态生成只写体验优化

### 输入

```text
目标岗位：剪映 AIGC
简历：参与多模态内容生成项目，优化用户体验。
真实情况：主要接了图片生成 API，做 prompt 和参数配置。
```

### 必须诊断

- “多模态内容生成项目”可以保留，但不能写模型优化。
- 必须追问输入模态、输出模态、生成链路、失败样例、审核和延迟。
- 必须对齐剪映：影像创作、生成链路编排、实时交互体验。

### 必须追问

1. 输入是文本、图片、视频还是模板？
2. 输出如何进入用户编辑链路？
3. 生成失败、违规、低质量如何处理？
4. 延迟和成本如何记录？
5. 是否有人审/重试/降级？

### 安全表达

```text
参与多模态生成能力接入原型，负责 Prompt 模板、生成参数配置和输出样例评估；围绕生成失败、风格不一致、内容安全和接口延迟等问题整理 bad case，并设计重试、降级和人工审核策略。
```

## Eval 8：后端能力被忽略

### 输入

```text
目标岗位：AIGC 工程实习
简历：参与 AI 功能开发，完成接口联调。
真实情况：写过 Python/FastAPI 接口，没怎么写在简历里。
```

### 必须诊断

- AIGC 岗也看工程落地，接口能力是加分项。
- 必须追问 API 契约、错误码、日志、限流、超时、重试。
- 必须结合 AI 生成链路：调用模型、缓存、异步、队列、监控。

### 安全表达

```text
参与 AI 生成能力的服务化接入，负责 FastAPI 接口封装、模型调用参数校验和错误返回处理；针对模型接口超时、结果格式异常和调用失败等场景补充日志追踪、失败重试和降级策略。
```

## Eval 10：JD 匹配失败

### 输入

```text
目标岗位：剪映 AIGC/Agent/RAG/MCP
简历：做过传统图像分类课程项目，使用 CNN 识别猫狗。
真实情况：没有实习，只有课程项目。
```

### 必须诊断

- 直接匹配弱。
- 不能强行包装成剪映 AIGC 业务。
- 可改造成多模态/影像创作相关 demo，但必须标为补做。

### 必须补强

- 迁移到图像编辑/风格分类/素材标签。
- 接入生成模型或多模态模型。
- 增加 AI 能力评估、bad case、服务接口。

### 安全表达

```text
基于图像分类课程项目扩展影像内容理解 demo，负责数据预处理、baseline 训练和错误样例分析；计划结合剪映影像创作场景补充素材标签、多模态检索或生成能力评估，以增强与 AIGC 工程岗位的匹配度。
```

## Eval 11：大模型算法岗，概念会说但缺证据

### 输入

```text
目标岗位：大模型算法实习
简历：负责大模型训练和对齐优化，显著提升效果。
真实情况：实际没有做预训练和 RLHF，只做了 RAG、Prompt、少量 LoRA 试验。
```

### 必须诊断

- “负责大模型训练和对齐优化”越界，必须降级。
- 必须区分：模型算法工作 vs 应用工程工作。
- 必须追问 LoRA 试验细节：数据、参数、评测口径。
- 必须追问 RAG 与微调取舍依据。
- 必须追问延迟、成本与质量评测闭环。

### 必须追问

1. 是否做过分布式训练（DP/TP/PP/FSDP）？
2. 是否做过 SFT/RLHF/DPO，数据与损失如何定义？
3. LoRA 的 rank、学习率、epoch 如何选？
4. 如何比较“只做 RAG”和“RAG+LoRA”的收益差异？
5. 指标是否包含准确性、引用质量、延迟和成本？

### 安全表达

```text
参与大模型应用算法优化，负责 RAG 检索链路调优、Prompt 版本迭代和小规模 LoRA 试验；围绕召回质量、引用准确性、响应延迟和成本指标构建评测样例，梳理幻觉与失败 case，为后续模型微调与工程化优化提供依据。
```

## 使用规则

当 Skill 处理用户简历时，至少匹配一个 eval 模式。如果匹配不到，说明当前案例覆盖不足，应输出新的 eval 建议。
