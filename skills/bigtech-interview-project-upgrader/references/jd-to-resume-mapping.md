# JD to Resume Mapping

目标：把目标 JD 拆成可验证能力项，再映射到用户简历中的真实证据、缺口和可补强动作。不要只做关键词匹配。

`TODO` 说明：文中表格里的 `TODO` 用于占位，表示需要按用户的 JD 与经历替换填写。

## 一、处理步骤

1. 提取 JD 中的核心任务、加分项、硬性要求和隐含能力。
2. 把每个 JD 能力项映射到用户经历中的项目、论文、实习、技能或竞赛。
3. 标记证据强度：强证据、弱证据、无证据、补做后可写。
4. 判断简历排序：哪些项目应该前置，哪些应该压缩。
5. 生成投递策略：主叙事、补强优先级、面试高危点。

## 三、能力项分类

### 业务任务

看 JD 要用户做什么，而不是只看技术词。

- 参与产品功能开发。
- 引入 AI 能力。
- 编排 AI 生成链路。
- 协同产品/算法团队。
- 落地技术方案。

映射时要找：

- 用户项目服务什么业务。
- 输入输出是什么。
- 有没有上下游和使用者。
- 是否只是 demo，还是内部试用/生产。

### 技术链路

- Prompt/RAG 优化。
- MCP 协议链路。
- 多模态内容生成。
- 实时交互体验。
- 性能调优。

映射时要区分：

- 已做：真实参与过。
- 近似：做过相邻能力，例如 HTTP tool call 接近但不等于 MCP。
- 缺失：完全没有证据。
- 可补做：能在 1-7 天内补一个可信 demo 或报告。

### 基础能力

- 编程语言。
- 数据结构和算法。
- 操作系统。
- 逻辑抽象和拆分。

映射时不要只写“熟悉”。要找：

- 项目里有没有任务拆解、状态机、并发、缓存、队列、日志、性能分析。
- 竞赛/论文是否能证明算法能力。
- 面试中会转到哪些八股和场景题。

## 五、高危词处理

| JD 关键词 | 没证据时不要写 | 安全替代表达 |
| --- | --- | --- |
| MCP | 熟悉/搭建 MCP 链路 | 了解 MCP 工具调用思想，补做最小 demo 后再写 |
| 性能调优 | 优化性能 | 记录节点耗时、延迟和失败原因，补做小规模对比 |
| 多模态生成 | 参与多模态模型优化 | 接入图像/文本生成能力，整理生成失败样例和链路设计 |
| 生产落地 | 上线生产 | 完成 demo/内部试用/业务流程验证 |
| 效果提升 | 提升 X% | 基于样例集观察到变化，补完整指标后再写 |

## 六、剪映 AIGC 岗映射示例

| JD 能力项 | 用户小厂 Agent/RAG 项目如何映射 |
| --- | --- |
| AI 生成链路编排 | 多节点工作流、章节抽取、检索、生成、后处理 |
| Prompt/RAG 优化 | 抽取 Prompt、chunk、向量召回、rerank、引用校验 |
| MCP 工具链 | 当前若没有 MCP，只能写工具调用/HTTP tool；建议补 MCP demo |
| 多模态内容 | 文档图片检索插入是弱相关，不等于视频/图像生成 |
| 性能调优 | 需要补节点耗时、并行耗时、API 延迟、失败重试 |
| 产品落地 | 需要说明使用者、使用流程、人工复核和限制 |
