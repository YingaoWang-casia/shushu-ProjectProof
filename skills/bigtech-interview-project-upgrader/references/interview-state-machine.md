# Interview State Machine

目标：把一次性建议变成多轮训练流程。每一轮都要更新真实性边界、风险、分数和下一步。

## 一、状态定义

| 状态 | 进入条件 | 主要任务 | 退出条件 |
| --- | --- | --- | --- |
| S0 Intake | 用户只给模糊经历/JD | 收集简历、JD、真实边界、证据 | 至少拿到 JD + 项目原文 |
| S1 Truth Audit | 有简历/JD但证据不清 | 判断做过/参与/待补做/不能写 | 每条强 claim 有风险标记 |
| S2 JD Mapping | 有目标岗位 | 拆 JD 并映射经历 | 得到主卖点和最大缺口 |
| S3 Production Gap | 有项目主线 | 对照大厂生产细节找差距 | 输出 5-8 个可追问缺口 |
| S4 Evidence Build | 缺证据 | 给半天/1天/3天/1周补证据任务 | 用户能补至少 3 个强证据 |
| S5 Resume Rewrite | 证据足够或可降级 | 产出三档 bullet | 每条 bullet 有证据依赖 |
| S6 Interview Drill | 用户要模拟面试 | 逐轮追问并评分 | 用户能答核心链路和 bad case |
| S7 Final Pack | 投递前 | 输出最终简历、叙事、追问、防线 | 给最终分数和投递建议 |

## 二、状态转移规则

- S0 信息不足时，不允许进入 S5。
- S1 发现 C3 指标无证据时，必须降级或进入 S4。
- S2 发现 JD 关键词无证据时，标记为“不建议硬蹭”或“补做后可写”。
- S3 发现生产级缺口时，不能只批评，必须给最小可补证据动作。
- S5 输出偏强版时，必须标注“不能现在直接写的原因”。
- S6 每轮只问 5-8 个问题，用户回答后再追问，不一次性轰炸。
- S7 前必须重新打 SP/SSP 分数。

## 三、每轮训练输出

每轮结束必须输出：

```text
本轮状态：
通过点：
新暴露风险：
需要降级的简历表达：
可以升级的表达：
分数变化：
下一轮问题：
本轮作业：
```

## 四、追问加压策略

### 第 1 层：事实核验

- 你具体做了哪部分？
- 哪些是同事做的？
- 项目是否上线或内部试用？
- 证据在哪里？

### 第 2 层：链路细节

- 输入是什么？
- 输出给谁用？
- 中间状态怎么流转？
- 失败在哪里发生？

### 第 3 层：生产差距

- 规模变大怎么办？
- 延迟变高怎么办？
- 权限怎么做？
- 出错怎么追踪？

### 第 4 层：八股转场

- 你用了检索，向量检索/BM25/rerank 原理是什么？
- 你用了并行，线程/协程/队列/幂等怎么考虑？
- 你用了评估，precision/recall/F1/AUC 怎么选？

### 第 5 层：复盘与演进

- 如果重做，你会怎么设计？
- 小厂方案迁移到大厂要补什么？
- 哪些没有做，为什么？

## 五、失败处理

如果用户回答不上：

1. 不继续扩散。
2. 标记为“高危穿帮点”。
3. 给一个保守回答模板。
4. 给一个补证据任务。
5. 降低相关简历表达强度。

## 六、完成标准

达到以下标准，才建议进入投递版输出：

- 能 2-3 分钟讲清项目。
- 能说清个人贡献边界。
- 至少有 5 个真实 bad case。
- 至少有 3 个可展示证据。
- 强表达没有无证据 C3 claim。
- 能回答目标 JD 的 5 个核心追问。
