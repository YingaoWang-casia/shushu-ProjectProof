# Role: 大模型 / RAG / LLM 应用

适用：大模型应用开发、RAG、知识库问答、企业智能助手、LLM 平台、模型评估、AI 产品工程。

## 大厂看重点

- 不是“会调 API”，而是能让 LLM 稳定接入业务流程。
- 能讲清 RAG 链路：数据接入、切分、向量化、召回、重排、prompt、生成、引用、评估。
- 能处理幻觉、格式错误、召回不准、上下文过长、权限隔离、成本和延迟。
- 有评估意识：离线评估集、bad case、人工标注、命中率、引用准确率、拒答率、延迟、成本。
- 如果涉及文档 RAG，必须追问文档解析细节：表格、跨页、页眉页脚、目录、扫描件、权限、增量索引。优先读取 `document-rag-production-gaps.md`。

## Toy 感

- 只写“调用 OpenAI/通义/DeepSeek API 实现问答”。
- 没有知识库构建、检索、评估、引用和权限。
- 没有 bad case：幻觉、召回错、引用错、答案不可控。
- 没有成本、延迟、上下文长度、prompt 版本。
- 把 prompt 调参说成模型训练。
- 没考虑文档解析质量：表格被打散、跨页段落断裂、目录/页眉污染召回、引用没有页码。

## 可补强动作

半天：

- 整理 10 条问答 bad case：无答案、召回错、幻觉、格式错、权限问题。
- 写出 RAG 主链路图：文档 -> chunk -> embedding -> vector store -> retrieval -> rerank -> prompt -> answer。
- 补 prompt 版本记录和测试样例。

1 天：

- 增加引用来源和“无依据拒答”策略。
- 增加结构化输出校验或答案长度/格式约束。
- 记录 token、延迟、模型、prompt version、retrieved chunks。
- 对文档 RAG 补 metadata：doc_id、page、section、chunk_id、version。
- 整理表格、跨页段落、页眉页脚污染、引用错位等文档 bad case。

3 天：

- 做一个小型评估集：20-50 条 query，标注正确答案、相关文档、预期拒答。
- 对比不同 chunk size、top_k、reranker、prompt 的效果。
- 输出 RAG 质量报告：召回命中、答案可用、引用准确、平均延迟。
- 增加 query-answer-evidence 评估集，区分 fact/table/summary/procedure/permission 问题。
- 对表格问题单独评估：表头关联、单位、跨页表格、精确数值召回。

1 周：

- 加权限过滤、多知识库隔离、缓存和失败 fallback。
- 做管理后台：文档上传、索引状态、问答记录、bad case 标注。
- 接入监控：错误率、超时率、token 成本、命中率趋势。

## 高频追问

1. RAG 和直接把全文塞进 prompt 的区别是什么？
2. chunk size 怎么选？overlap 怎么设？
3. embedding 模型怎么选？中文效果怎么评估？
4. top_k 取多少？召回太多/太少会怎样？
5. 什么时候需要 rerank？
6. 怎么处理模型幻觉？
7. 如果知识库里没有答案，怎么拒答？
8. 权限隔离怎么做？用户能否检索到不该看的文档？
9. token 成本和延迟怎么控制？
10. 你怎么证明效果变好了？
11. PDF 里的表格怎么处理？直接转文本有什么问题？
12. 段落跨页、表格跨页、页眉页脚污染召回怎么办？
13. 文档更新后索引怎么增量更新？
14. 引用粒度是文档、页码、段落还是表格单元格？

## 回答防线

- 如果没做模型训练：明确说“没有训练底座模型，我做的是 LLM 应用工程/RAG 链路”。
- 如果没上线：说清是 demo、内部试用还是本地验证，并补评估集和运行截图作为证据。
- 如果没指标：补人工标注样例、抽样评估和 bad case 表，不写虚假准确率。
