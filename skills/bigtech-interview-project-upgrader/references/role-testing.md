# Role: 测试开发 / 质量工程

适用：测试开发、自动化测试、质量平台、接口测试、E2E、压测、稳定性。

## 大厂看重点

- 能从业务风险设计测试，而不是只写脚本。
- 能讲清单测、接口测试、集成测试、E2E、mock、测试数据和 CI。
- 能定位失败、沉淀用例、提升回归效率。

## Toy 感

- 只写“编写测试用例”。
- 没有覆盖核心路径和异常路径。
- 没有 mock、测试数据、断言、报告。
- 没有 CI 或回归策略。

## 可补强动作

半天：

- 梳理核心业务路径和异常路径。
- 补测试用例表：前置条件、输入、期望、断言。
- 整理历史 bug 和回归用例。

1 天：

- 补接口测试或核心函数单测。
- 增加 mock 和测试数据构造。
- 输出测试报告。

3 天：

- 接入 CI，失败自动输出日志和报告。
- 增加 E2E 或关键流程自动化。
- 加覆盖率和 flaky case 分析。

1 周：

- 做质量看板：通过率、失败原因、覆盖率、耗时趋势。
- 做压测和稳定性验证。

## 简历表达素材

```text
参与 TODO 系统质量保障，负责核心接口测试、异常用例设计和回归用例沉淀；围绕参数校验、权限、状态流转和接口失败等场景补充自动化测试，并输出测试报告支持版本迭代。
```
