# Role: 前端开发 / Web / 可视化

适用：React、Vue、Next.js、管理后台、数据可视化、低代码、内部工具、前端工程化。

## 大厂看重点

- 不只是页面还原，要体现组件设计、状态管理、性能、稳定性、工程化和体验。
- 能讲清数据流：用户操作 -> 状态变化 -> 请求 -> 渲染 -> 错误态。
- 能处理复杂表单、权限、路由、缓存、大列表、弱网和兼容性。

## Toy 感

- 只写“完成页面开发”。
- 没有组件抽象、状态管理、错误态、加载态。
- 没有性能优化：首屏、包体积、大列表、重复渲染。
- 没有权限、路由、表单校验。
- 没有测试、埋点、监控或工程化配置。

## 可补强动作

半天：

- 补页面数据流和组件结构图。
- 给关键表单补校验、加载态、错误态、空状态。
- 整理 5 个前端 bad case：接口失败、字段为空、超长文本、弱网、权限不足。

1 天：

- 抽一个可复用组件：表格、筛选器、弹窗表单、状态标签。
- 补权限路由或按钮级权限。
- 增加请求封装、统一错误处理和 loading 管理。

3 天：

- 做性能优化：懒加载、代码分割、虚拟列表、memo、缓存。
- 加 E2E 或组件测试。
- 增加埋点或前端异常监控。

1 周：

- 做前端工程化：lint、format、CI、组件文档、设计 token。
- 做复杂业务流：审批、复核、状态流转、可视化分析。
- 做可访问性、国际化或移动端适配。

```text
参与内部管理后台前端开发，负责 TODO 页面和表单交互实现；补充加载态、错误态和字段校验，支持接口联调和业务流程演示。
```

标准版：

```text
参与 TODO 业务后台前端开发，负责列表筛选、详情弹窗和状态流转页面；封装请求处理、表单校验和权限控制逻辑，针对接口失败、空数据和超长字段等场景补充错误态和兜底展示。
```

偏强版：

```text
负责 TODO 前端模块从页面实现到可维护组件化的改造，抽象表格筛选、表单弹窗和状态标签组件；通过虚拟列表/懒加载/请求缓存优化大数据量展示体验，并补充异常监控和 E2E 用例。
```

## 高频追问

1. 页面状态怎么管理？为什么不用/用 Redux、Pinia、Zustand？
2. 接口失败怎么处理？
3. 表单重复提交怎么防？
4. 权限路由怎么做？
5. 大列表卡顿怎么优化？
6. 首屏慢怎么分析？
7. 组件怎么拆？怎么保证复用不过度？
8. 前端监控记录什么？
9. 如何做 E2E 测试？
10. 如何和后端定义接口契约？

## 回答防线

- 只做页面也能讲强：从 UI 还原升级到数据流、异常态、权限、性能和工程化。
- 没有线上监控时，不写“线上稳定性”，写“补充错误态、日志上报方案或测试用例”。
