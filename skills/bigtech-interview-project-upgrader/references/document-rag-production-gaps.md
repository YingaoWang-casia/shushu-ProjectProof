# 文档 RAG / Agent 生产级差距清单

很多小厂 Agent/RAG 项目只做到“上传文档 -> 向量化 -> 问答”，但大厂面试会追问文档解析、版面结构、表格、跨页、权限、增量更新和评估。这个文件专门补这些小厂项目常忽略的生产细节。

## 一、小厂 demo 和大厂生产系统的差距

| 小厂常见做法 | 大厂会追问 | 可信补强 |
| --- | --- | --- |
| 直接把 PDF/Word 转纯文本 | 表格、图片、页眉页脚、脚注、目录怎么处理？ | 建立文档解析策略和 bad case 集 |
| 固定长度切 chunk | 跨页段落、标题层级、表格行列被切断怎么办？ | 按标题/段落/表格语义切分，保留 metadata |
| 只做向量召回 | 关键词、编号、专有名词、表格查询召回差怎么办？ | 混合检索：BM25 + 向量 + rerank |
| 没有引用来源 | 答案是否能追溯到页码/段落/表格？ | 输出 doc_id、page、section、chunk_id |
| 没有评估集 | 怎么证明 RAG 效果？ | 构造 query-answer-evidence 评估集 |
| 没有权限 | 用户能否问到不该看的文档？ | 文档级/段落级 ACL 过滤 |
| 全量重建索引 | 文档频繁更新怎么办？ | 增量索引、版本号、失效策略 |

## 二、文档解析细节

### 1. 文档类型

面试官会问：

- PDF 是文本型还是扫描件？
- Word、PPT、Excel、HTML、Markdown 是否都支持？
- 图片、表格、公式、脚注、目录怎么处理？
- 页码和标题层级能否保留？

回答要点：

- 文本型 PDF 可以抽取文本和位置信息。
- 扫描件需要 OCR，且要处理识别错误和版面顺序。
- Word/PPT/Excel 不宜都当纯文本，表格和标题结构要单独处理。
- 每个 chunk 应保留 `doc_id/page/section/title/source/version` 等 metadata。

### 2. 页眉页脚和目录

常见 bad case：

- 每页页眉页脚重复进入 chunk，污染召回。
- 目录页被当作正文，回答只引用目录。
- 页码、版权声明、公司 footer 被召回。

补强策略：

- 识别高频重复文本并过滤。
- 对目录、封面、版权页打标签，默认不进入主召回。
- 保留页码 metadata，但不要让页码文本污染语义。

### 3. 跨页和换页

常见 bad case：

- 一个段落跨页，被切成两段，召回只命中半句。
- 标题在上一页，正文在下一页，chunk 丢失上下文。
- 表格跨页，表头在第一页，数据在下一页。

补强策略：

- 按标题和段落边界切分，而不是只按页切。
- 对跨页段落做 merge，保留起止页码。
- 对跨页表格复制/关联表头。
- chunk metadata 记录 `page_start` 和 `page_end`。

## 三、表格处理

表格是文档 RAG 面试高频坑。

### 面试官会问

1. 表格直接转文本会丢什么？
2. 表头和单元格如何关联？
3. 跨页表格怎么处理？
4. 用户问“某某指标是多少”时，如何从表格召回？
5. 表格适合向量召回、关键词召回，还是结构化查询？
6. 表格里的数字单位、百分比、日期怎么处理？

### 常见错误

- 表格行列顺序错乱。
- 表头丢失，单元格变成孤立数字。
- 合并单元格展开错误。
- 跨页表格第二页没有表头。
- 单位在表头，数值在单元格，回答时丢单位。
- 表格被切成多个 chunk，query 找不到完整上下文。

### 补强策略

- 表格单独解析，不和正文混切。
- 用 Markdown table 或 JSON 保存表格。
- 每一行转成“表头: 值”的语义化文本。
- 保留 caption、表号、所在章节、页码。
- 跨页表格复制表头，并用 table_id 关联。
- 数字字段保留单位和原始字符串。
- 对精确数值查询，优先关键词/结构化检索，再结合向量召回。

### 简历可写表达

```text
针对企业文档中表格、跨页段落和页眉页脚等解析噪声，设计文档预处理规则，保留页码、标题层级和表格字段 metadata；整理表格召回错误、引用错位和跨页上下文缺失等 bad case，为 RAG 评估和引用校验提供依据。
```

## 四、Chunk 策略

### 面试官会问

- chunk size 怎么选？
- overlap 多少合适？
- 为什么固定长度切分不好？
- 标题、列表、表格、代码块怎么切？
- chunk 太长/太短分别有什么问题？

### 回答框架

- 固定长度简单，但容易切断语义。
- 生产中优先按标题、段落、列表、表格、语义单元切。
- chunk 太短：上下文不够，回答碎片化。
- chunk 太长：召回不准，token 成本高，噪声多。
- overlap 用来缓解边界信息丢失，但过大会造成重复召回和成本上升。
- 最好用评估集对比不同 chunk 策略。

## 五、检索与重排

### 只用向量召回的问题

- 数字、编号、专有名词、法规条款、表格字段可能召回差。
- 用户 query 很短时语义不充分。
- 近义但事实不同的 chunk 可能被误召回。

### 补强策略

- 混合检索：BM25/关键词 + 向量召回。
- query rewrite：把口语问题扩展成检索 query。
- rerank：对 topN 候选按 query-doc 相关性重排。
- metadata filter：按文档类型、权限、时间、部门过滤。
- 对表格/编号/条款类问题，增加精确匹配。

## 六、引用和可信回答

### 面试官会问

- 答案引用怎么做？
- 模型会不会编引用？
- 引用粒度是文档、页码、段落还是表格单元格？
- 如果召回内容互相矛盾，怎么回答？

### 回答框架

- 生成答案时必须基于 retrieved chunks。
- 每个 chunk 有 doc_id、page、section、chunk_id。
- 答案后附引用，引用只能来自召回内容。
- 对低置信度或无证据问题拒答。
- 矛盾内容按版本、时间、权限、权威来源排序，必要时提示人工确认。

## 七、权限和多租户

常见追问：

- 用户是否能检索到无权限文档？
- 权限是在召回前过滤还是召回后过滤？
- 文档权限变更后索引如何更新？
- 多租户数据怎么隔离？

回答要点：

- 权限过滤应尽量在召回前或召回过程中做 metadata filter，避免召回后泄露。
- chunk metadata 带 ACL、tenant_id、department、doc_version。
- 权限变更要触发索引 metadata 更新或重建。
- 日志中不能泄露敏感文本。

## 八、增量更新和版本管理

面试官会问：

- 文档更新后旧答案怎么办？
- 全量重建太慢怎么办？
- 如何知道哪个答案来自哪个版本？

回答要点：

- 文档有 version/hash/update_time。
- 增量更新变更文档对应 chunk。
- 旧 chunk 标记失效或按版本隔离。
- 答案引用里带版本信息。
- 索引构建有状态：pending/indexing/ready/failed。

## 九、评估体系

RAG 不能只看“感觉回答还行”。

### 评估集字段

```text
query
expected_answer
evidence_doc
evidence_page
evidence_section
answerable: yes/no
question_type: fact/table/summary/procedure/permission
```

### 指标

- retrieval hit rate：正确证据是否进 topK。
- answer correctness：答案是否正确。
- citation accuracy：引用是否支撑答案。
- refusal accuracy：无答案时是否拒答。
- latency：检索、重排、生成耗时。
- cost：token 和模型调用成本。

### Bad case 分类

- 召回不到。
- 召回到了但排序靠后。
- 表格解析错。
- 跨页上下文丢失。
- 引用错位。
- 无证据仍回答。
- 权限过滤错误。

## 十、小厂项目如何安全包装

如果你小厂只做了简单 Agent/RAG，可以这样说：

保守版：

```text
参与内部文档问答 Agent 原型开发，负责文档样例整理、Prompt 模板维护和问答 bad case 记录；梳理表格解析、跨页段落、引用错位和无依据回答等问题，为后续 RAG 评估和工程化改造提供依据。
```

标准版：

```text
参与内部文档 RAG/Agent 工具开发，负责文档预处理、chunk 策略和结构化输出校验；针对表格召回不准、跨页上下文缺失、页眉页脚污染和模型无依据回答等 bad case，补充 metadata、引用校验和拒答策略。
```

偏强版，必须补做后再写：

```text
负责将内部文档问答 Agent 从 demo 改造为可评估的 RAG 流程，设计文档解析、语义切分、混合检索、引用校验和 bad case 回归机制；基于 query-answer-evidence 评估集统计召回命中、引用准确和拒答效果，沉淀文档 RAG 质量报告。
```

## 十一、面试防线

### Q：你当时没考虑表格和跨页问题，现在怎么补？

A：当时小厂项目更偏 demo，主要验证文档问答链路，没有完整处理复杂版面。现在复盘，我会把文档解析单独作为一层：区分正文、表格、目录、页眉页脚和扫描件；对 chunk 保留 page、section、table_id 等 metadata；针对表格召回、跨页段落和引用错位建立 bad case 集，再用评估集验证召回和答案引用效果。

### Q：RAG 效果怎么评估？

A：不能只凭主观感觉。我会构造 query-answer-evidence 评估集，标注每个问题的标准答案和证据页，分别统计 topK 召回命中、答案正确性、引用准确性、拒答准确性、延迟和成本。

### Q：表格为什么难？

A：表格不是线性文本。表头、行列关系、合并单元格、单位、跨页表头都会影响语义。直接转纯文本容易让数字失去上下文，所以需要表格单独解析，保留 caption、header、row、page 和 table_id，并对精确数值问题结合关键词或结构化检索。
