# Question Tree Playbook

题库只能覆盖知识点，追问树才能模拟真实大厂面试。这个文件定义如何根据用户回答继续追问。

## 一、通用追问树

### Root：介绍项目

问题：

```text
请用 2 分钟介绍这个项目：背景、目标、你的职责、方案、结果。
```

如果用户讲不出业务：

- 追问：用户是谁？这个结果给谁用？不用这个系统会怎样？
- 风险：项目像课程 demo。
- 要求补证据：业务流程图、下游使用方、输入输出。

如果用户讲不出职责：

- 追问：哪些代码/文档/规则是你做的？同事做了什么？
- 风险：贡献边界不清。
- 要求补证据：代码、日报、模块清单。

如果用户讲不出结果：

- 追问：有没有离线指标、抽样验证、质量报告、bad case 对比？
- 风险：只能写完成任务，不能写效果。
- 要求补证据：评估表、日志、样例。

## 二、算法项目追问树

### Node A：数据

问题：数据从哪里来，标签怎么来？

回答“业务库/日志”：

- 追问：字段有哪些？样本量多少？时间跨度？是否有噪声？
- 再追：训练/验证/测试怎么切，是否按时间切？

回答“不清楚”：

- 判定：高危。
- 降级表达：只能写参与实验，不能写负责完整算法流程。

### Node B：Baseline

问题：baseline 是什么？

回答“没有 baseline”：

- 追问：原业务规则是什么？人工流程是什么？开源模型默认效果是什么？
- 建议：补一个规则 baseline 或现有模型 baseline。

回答“直接用大模型/API”：

- 追问：你怎么证明 prompt/流程有效？有无评估集？
- 建议：构造 20-50 条样例做回归。

### Node C：指标

问题：指标怎么计算？

回答“准确率”：

- 追问：类别是否均衡？precision/recall/F1 呢？
- 场景题：误杀和漏召哪个业务成本更高？

回答“提升 X%”：

- 追问：和什么比？数据划分？随机种子？样本量？是否显著？
- 风险：没有口径不能写具体提升。

## 三、大模型算法岗追问树

### Node A：模型原理

问题：你项目里用到的模型结构是什么？为什么选它？

回答“用了 Transformer，很强”：

- 追问：Self-Attention 怎么算？为什么要除 `sqrt(d_k)`？
- 再追：Pre-LN 和 Post-LN 区别？为什么 decoder-only 常用于生成？

回答“说不清结构，只会调 API”：

- 判定：原理深度不足。
- 降级表达：偏 LLM 应用工程，不要写算法优化或模型设计。

### Node B：训练/微调/对齐

问题：你做的是预训练、微调还是应用层优化？

回答“做了微调”：

- 追问：LoRA/QLoRA 还是 full fine-tuning？rank、学习率、epoch 怎么选？
- 再追：和 RAG 相比收益在哪里？有没有遗忘原能力？

回答“做了对齐”：

- 追问：SFT、RLHF、DPO 各解决什么问题？
- 再追：偏好数据噪声、reward hacking、过度拒答如何处理？

### Node C：推理与评测

问题：你如何证明方案更好？

回答“主观感觉更好”：

- 判定：高危。
- 追问：离线评测集、人评、线上指标分别是什么？
- 再追：TTFT、TPOT、吞吐、P95 延迟、成本有没有记录？

回答“只看单一 accuracy”：

- 风险：指标维度不足。
- 建议：补任务成功率、引用准确率、拒答准确率、时延和成本。

## 四、RAG / Agent 追问树

### Node A：文档来源

问题：文档类型是什么？PDF、Word、Excel、网页还是数据库？

回答“PDF/Word”：

- 追问：表格、跨页、页眉页脚、目录怎么处理？
- 再追：chunk 是否保留 page、section、table_id？

回答“没考虑”：

- 防线：承认 demo 阶段没完整处理，补生产级改造方案。
- 补证据：整理 5 个文档解析 bad case。

### Node B：检索

问题：只用向量召回吗？

回答“是”：

- 追问：数字、编号、专有名词、表格字段召回差怎么办？
- 建议：混合检索 BM25 + vector + rerank。

回答“不知道 top_k”：

- 风险：RAG 细节不足。
- 补证据：对比 top_k/chunk_size 的小实验。

### Node C：答案可信

问题：怎么保证答案有依据？

回答“prompt 里要求”：

- 追问：模型会不会编引用？引用粒度是什么？
- 建议：引用只能来自 retrieved chunks，低置信拒答。

## 五、推荐 / 搜索追问树

### Node A：链路

问题：你的系统是召回、排序还是完整推荐链路？

回答“只做模型”：

- 追问：模型在召回/粗排/精排哪一层？
- 建议：不要包装成完整推荐系统，写清具体层级。

### Node B：线上离线

问题：离线指标为什么能代表业务？

回答“指标提升所以好”：

- 追问：线上 CTR/转化可能为什么不涨？
- 场景题：分布变化、曝光偏差、位置偏差、特征延迟。

## 六、语音追问树

### Node A：音频数据

问题：音频采样率、格式、场景是什么？

回答“不清楚”：

- 判定：语音项目可信度不足。
- 补证据：记录采样率、时长、格式、噪声场景。

### Node B：指标

问题：WER/CER 怎么算？

回答不上：

- 降级：不能写语音算法优化，只能写语音 API 应用/测试。
- 补证据：做 20 条样例转写评估。

## 七、结束评分

每轮追问结束，必须给：

```text
通过的问题：
卡住的问题：
高危穿帮点：
补证据动作：
下一轮追问方向：
```
