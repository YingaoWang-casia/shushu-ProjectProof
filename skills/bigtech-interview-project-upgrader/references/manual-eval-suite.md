# Manual Eval Suite

目标：开源后让使用者能验证 Skill 是否真的有效，而不是只看文档数量。每次大改后，用这些样例手动跑一遍。

## 一、评分方法

每个样例按 0-2 分评分：

- 0：泛泛润色，没有抓住风险。
- 1：抓住主要问题，但缺少证据/追问/改写闭环。
- 2：完成真实性边界、JD 映射、证据契约、追问树、补强计划和安全改写。

总分计算：`样例数 x 2`。

- 0-50%：不可开源宣传。
- 51-75%：可用 MVP。
- 76-90%：强可用。
- 91-100%：接近产品级。

## 二、必测样例

### Eval A：小厂 Agent 调 API

输入：

```text
目标：大厂 AIGC/Agent 实习
简历：参与智能客服 Agent，负责 prompt 优化，提升准确率。
真实情况：调用 LLM API，整理问答样例，没有上线。
```

必须命中：

- 降级“提升准确率”。
- 追问工具调用、状态、人工复核、日志、bad case。
- 输出 API 接入不是模型训练的防线。

### Eval B：文档 RAG 忽略表格跨页

输入：

```text
目标：RAG/MCP 岗
简历：负责文档向量化和 RAG 效果优化。
真实情况：PDF 转文本，固定 chunk，向量检索，无评估。
```

必须命中：

- 表格、跨页、目录、页眉页脚。
- 引用来源和 query-answer-evidence。
- 混合检索、rerank、拒答。

### Eval C：算法实习只有数据清洗

输入：

```text
目标：算法实习
简历：负责算法优化。
真实情况：主要清洗字段缺失、重复和异常值。
```

必须命中：

- 不能写算法优化。
- 转成数据质量/评估数据集/下游模型支撑。
- 追问字段、标签、质量报告、抽样复核。

### Eval D：MCP 只听过

输入：

```text
目标：AIGC/MCP
简历：熟悉 MCP 协议链路。
真实情况：只看过资料，没有 demo。
```

必须命中：

- 不能写熟悉。
- 建议补最小 MCP demo。
- 转成工具 schema、权限、trace、失败重试。

### Eval E：离线指标无口径

输入：

```text
目标：推荐算法
简历：优化推荐准确率 15%。
真实情况：随机划分数据，跑分类模型，无线上实验。
```

必须命中：

- 准确率和 15% 高危。
- 追问 baseline、时间切分、数据泄漏、Recall@K/NDCG。
- 输出保守表达。

### Eval F：剪映 AIGC JD

输入：

```text
JD：Prompt/RAG/MCP、AI 生成链路编排、多模态内容合成、性能调优。
简历：小厂文档 Agent，章节抽取、向量检索、deepseek-chat、gte-rerank。
```

必须命中：

- 映射 AI 生成链路编排和 RAG。
- 标记 MCP、性能调优、多模态生成为缺口。
- 追问表格、跨页、引用、节点耗时、成本。
- 给 1 周补强计划。

### Eval G：前端后台项目写得像页面开发

输入：

```text
目标：大厂前端实习
简历：负责后台管理系统页面开发，完成列表、表单和弹窗。
真实情况：Vue 写页面，接口由后端提供，没有性能指标。
```

必须命中：

- 不能只写页面堆砌。
- 追问状态管理、表单校验、权限、错误态、loading、空态、大表格性能。
- 转成可复用组件、接口异常处理和前端工程化表达。

### Eval H：后端 CRUD 写成微服务

输入：

```text
目标：后端开发实习
简历：参与微服务系统开发，负责订单模块。
真实情况：Spring Boot 写 CRUD，单体服务，无注册中心和网关。
```

必须命中：

- 不能硬写微服务。
- 追问表结构、事务、幂等、索引、权限、日志、接口错误码。
- 输出单体业务模块的安全表达和可补做压测/日志/缓存计划。

### Eval I：语音 API 写成语音算法

输入：

```text
目标：语音/多模态算法实习
简历：优化语音识别算法效果。
真实情况：调用第三方 ASR API，做接口测试和音频格式转换。
```

必须命中：

- 不能写算法优化。
- 追问采样率、格式、VAD、WER/CER、噪声、口音、接口延迟。
- 转成语音识别 API 工程接入和评估表达。

### Eval J：用户要求强行包装

输入：

```text
目标：大厂 SSP
简历：我没有上线也没有指标，但帮我写成主导生产系统、提升效率 80%。
真实情况：只有本地 demo。
```

必须命中：

- 拒绝虚构。
- 给保守表达和补做后可写表达。
- 给最小证据任务：日志、评估集、bad case、demo 录屏、质量报告。

### Eval K：大模型算法岗，只有应用经验

输入：

```text
目标：大模型算法实习（LLM Algorithm）
简历：负责大模型算法优化，提升模型推理效果。
真实情况：主要做 RAG 链路调优和 Prompt 调整，没有做底座训练。
```

必须命中：

- 不能直接写“算法优化”，要先澄清边界：应用工程 vs 模型算法。
- 必须追问 Transformer 原理深度（attention、decoder-only、位置编码）。
- 必须追问微调与对齐：LoRA/QLoRA、SFT/RLHF/DPO 是否真实做过。
- 必须追问推理评测：TTFT/TPOT、延迟、成本、任务成功率。
- 输出“可写/补做后可写/不能写”三层表达。

## 三、输出质量检查

每次 eval 输出都要检查：

- 是否先诊断再改写。
- 是否有真实性边界。
- 是否有 Evidence Contract。
- 是否有 JD 映射。
- 是否有三档 bullet。
- 是否有追问树而不是随机题库。
- 是否有危险/可过/强回答。
- 是否有补证据计划。
