# 场景题 + 八股穿插追问

大厂项目面不会把“项目”和“八股”完全分开。面试官常用你的项目作为入口，把问题转到算法基础、系统设计、数据库、网络、OS、工程化、稳定性和业务判断。

## 追问方式

推荐节奏：

1. 从简历项目入手：你做了什么？
2. 追具体链路：输入、输出、状态、数据、指标。
3. 抽象成八股：为什么这么设计？基础原理是什么？
4. 变成场景题：如果线上坏了/规模变大/数据变脏怎么办？
5. 回到项目：你现在能补什么证据？

## 算法实习常见场景题

### 场景 1：离线指标提升，业务方说没效果

追问：

1. 离线指标和线上目标是否一致？
2. 样本分布是否和线上一致？
3. 是否只优化了头部样本？
4. 有没有数据泄漏？
5. 是否需要分层评估？

好回答要点：

- 承认离线指标不等于线上收益。
- 检查数据分布、样本权重、标签延迟、指标口径。
- 增加分层指标：新老用户、长尾、场景、时间段。
- 设计灰度/AB，而不是直接宣称有效。

### 场景 2：模型准确率很高，但 F1 很低

追问：

1. 是否类别不平衡？
2. precision 和 recall 分别是多少？
3. 阈值怎么选？
4. 业务更关心误杀还是漏召？

好回答要点：

- 准确率可能被多数类掩盖。
- 用 precision/recall/F1/AUC/PR-AUC。
- 阈值按业务成本选择。
- 输出混淆矩阵和错误样例。

### 场景 3：线上推理延迟突然升高

追问：

1. 是模型耗时、特征获取、网络、数据库还是下游依赖？
2. p50/p95/p99 分别是多少？
3. 是否有缓存、批处理、异步、降级？
4. 如何定位？

好回答要点：

- 先看 tracing 和分段耗时。
- 区分平均延迟和 tail latency。
- 用缓存、batch、模型压缩、异步队列、降级策略。
- 必须有日志和监控。

### 场景 4：数据上游字段变了，模型效果下降

追问：

1. 有没有 schema 校验？
2. 特征分布有没有漂移？
3. 是训练/推理特征不一致吗？
4. 怎么报警和回滚？

好回答要点：

- 加 schema check、空值率、分布漂移监控。
- 记录数据版本和特征版本。
- 失败时 fallback 到旧模型/规则。
- 补数据质量报告。

### 场景 5：小厂项目没有 AB，怎么证明价值

追问：

1. 没有线上实验，简历凭什么写结果？
2. 离线评估如何设计？
3. 人工复核怎么抽样？
4. 下一步如何上线验证？

好回答要点：

- 不写线上收益。
- 写离线评估、抽样人工复核、bad case 对比。
- 说明指标口径和限制。
- 设计灰度/AB 方案作为后续计划。

## 工程场景题

### 接口超时

回答框架：

- 定位：客户端、网关、服务、数据库、第三方、模型/API。
- 观察：trace id、分段耗时、错误码、日志、p95/p99。
- 处理：超时配置、重试退避、熔断、降级、缓存、异步队列。
- 简历补强：如果项目有接口，补 trace 日志和失败重试说明。

### 缓存不一致

回答框架：

- 先更新 DB 还是缓存？为什么？
- 删除缓存 vs 更新缓存。
- TTL、延迟双删、binlog 同步。
- 强一致还是最终一致，取决于业务。

### 重复提交

回答框架：

- 前端防重复点击只是辅助。
- 后端用幂等 key、唯一索引、状态机、分布式锁。
- 失败重试要保证不会重复写。

### 权限越权

回答框架：

- 认证 authentication 和授权 authorization 分开。
- 资源级权限、角色权限、数据隔离。
- 日志审计和敏感操作二次确认。

## 八股嵌入式提问模板

- 你项目里用到了缓存，那 Redis 常见数据结构有哪些？为什么不用本地缓存？
- 你项目里有接口，那 HTTP 和 RPC 区别是什么？GET/POST 幂等吗？
- 你项目里有数据库，那索引为什么能加速？B+ 树和哈希索引区别？
- 你项目里做了异步，那线程、进程、协程区别？队列积压怎么办？
- 你项目里做了模型推理，那 batch size 影响什么？CPU/GPU 瓶颈怎么判断？
- 你项目里有日志，那如何串起一次请求的完整链路？

## 回答评分

| 档位 | 表现 |
| --- | --- |
| 危险 | 只背定义，无法回到自己项目 |
| 可过 | 能解释概念，但没有项目证据 |
| 强 | 能结合项目说明取舍、限制和补强 |
| 高面评 | 能主动提出监控、回滚、指标和长期演进 |
