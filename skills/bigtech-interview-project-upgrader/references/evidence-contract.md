# Evidence Contract

简历里每一句强表达都必须有证据。这个文件定义“什么话需要什么证据”，防止项目包装过度。

## 一、Claim 等级

| 等级 | 表达强度 | 示例 | 证据要求 |
| --- | --- | --- | --- |
| C0 | 了解/参与 | 参与项目开发、了解链路 | 口头说明、项目文档 |
| C1 | 负责模块 | 负责数据清洗、接口联调、Prompt 维护 | 代码、日报、文档、截图 |
| C2 | 设计/优化 | 设计评估流程、优化召回策略 | 对比实验、bad case、设计文档 |
| C3 | 结果影响 | 提升 X%、降低延迟、上线生产 | 指标口径、日志、AB、线上记录 |

没有 C3 证据，不允许写具体线上收益。

## 二、常见表达与证据

| 简历表达 | 最低证据 | 缺证据时的安全写法 |
| --- | --- | --- |
| 负责数据清洗 | 清洗规则、样例、前后对比 | 参与数据清洗和异常样例整理 |
| 设计评估体系 | 评估集、指标、脚本、报告 | 梳理评估口径和 bad case |
| 优化模型效果 | baseline、对比实验、指标口径 | 对比不同模型/参数并记录结果 |
| 提升准确率 | 数据划分、指标脚本、对比表 | 在离线样例上观察到指标变化 |
| 上线系统 | 发布记录、用户反馈、线上日志 | 完成 demo/内部试用/本地验证 |
| 支撑业务使用 | 用户、流程、使用记录 | 支持业务流程验证 |
| 处理高并发 | 压测、QPS、架构设计、监控 | 设计可扩展方案或做小规模压测 |
| RAG 效果提升 | query-answer-evidence、召回命中、引用准确 | 整理 RAG bad case 和评估样例 |
| Agent 任务成功率 | 任务集、成功定义、日志 | 梳理工具调用失败样例 |

## 三、证据类型

强证据：

- 代码 diff。
- 实验报告。
- 指标表。
- 日志截图。
- 线上/内部试用记录。
- Bad case 表。
- 评估集。
- README/设计文档。

弱证据：

- 口头描述。
- 只有最终截图。
- 只有“老板说有效”。
- 没有口径的百分比。

## 四、证据缺失处理

如果用户没有证据：

1. 降级表达。
2. 标注“补做后可写”。
3. 给出最小补证据动作。

示例：

```text
不能写：优化 RAG 召回效果，提升准确率 20%。
可以写：整理 RAG 召回失败样例，梳理 chunk、top_k 和引用校验等优化方向。
补做后可写：基于 50 条 query-answer-evidence 样例对比不同 chunk/top_k 策略，统计召回命中和引用准确率。
```

## 五、输出要求

每次改写简历时，必须附：

```text
这句话依赖的证据：
当前证据是否足够：
如果面试追问，如何证明：
如果证据不足，降级版本：
```
