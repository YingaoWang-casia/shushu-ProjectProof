# SP / SSP Scorecard

用于判断一段小厂实习经历离大厂强面评还有多远。分数不是安慰用户，而是定位缺口。

## 一、评分维度

每项 0-5 分，总分 50。

| 维度 | 0-1 | 2-3 | 4-5 |
| --- | --- | --- | --- |
| 业务真实性 | 不知道用户和场景 | 有场景但流程粗 | 业务目标、用户、上下游清晰 |
| 贡献边界 | 说不清自己做什么 | 能说模块但证据弱 | 职责、边界、证据清楚 |
| 算法/技术深度 | 只调包/API | 有 baseline/规则/实验 | 有对比、消融、误差分析 |
| 数据理解 | 不知道数据来源 | 能说字段和规模 | 标签、噪声、划分、泄漏都清楚 |
| 评估可信度 | 没指标或口径 | 有离线指标 | 有评估集、分层、bad case |
| 工程闭环 | 一次性 demo | 有脚本/文档 | 有日志、测试、部署、监控思路 |
| 生产差距认知 | 不知道大厂会问什么 | 能说部分风险 | 能主动讲扩展、权限、回滚、成本 |
| 面试抗压 | 追问会崩 | 能答基础问题 | 能承认边界并给补强方案 |
| JD 匹配度 | 和岗位弱相关 | 部分命中关键词 | 能映射到岗位核心能力 |
| 成长/Ownership | 被动执行 | 完成任务 | 主动发现问题、沉淀方法 |

## 二、档位

| 总分 | 档位 | 解释 |
| --- | --- | --- |
| 0-20 | 高危 | 简历可能被追问穿，需要先补事实 |
| 21-30 | 普通可投 | 能投，但项目面不硬 |
| 31-38 | 强可投 | 有清晰叙事和基本防线 |
| 39-44 | SP 潜力 | 有 ownership、证据、取舍和复盘 |
| 45-50 | SSP 潜力 | 明显超出普通实习，能系统性拆问题并推动闭环 |

## 三、一票否决

出现以下情况，不给 SP/SSP：

- 虚构上线、指标、主导或大规模。
- 说不清个人贡献边界。
- 指标没有口径。
- 项目核心链路讲不清。
- 面试追问 bad case 时没有任何真实样例。
- 把 API 调用说成模型训练。

## 四、SP 信号

- 能指出项目限制而不慌。
- 能把小厂问题抽象成大厂也认可的能力：数据质量、评估、工程闭环、可观测性、取舍。
- 能说出至少 3 个生产级风险和应对。
- 有至少 1 个主动补强动作。
- 简历表达和证据匹配。

## 五、SSP 信号

- 能主动定义问题，而不是只完成任务。
- 能从业务、算法、工程三个层面拆解。
- 能设计评估体系，而不只调指标。
- 能提出迁移到大厂规模的架构演进。
- 能带出沉淀物：工具、规范、评估集、质量报告、复盘。
