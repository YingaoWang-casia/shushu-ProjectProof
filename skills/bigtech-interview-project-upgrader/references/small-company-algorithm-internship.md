# 小厂算法 / AI 实习经历升级主指南

适用：用户已经有 1-2 段小厂算法、AI 应用、数据挖掘、推荐、搜索、NLP、CV、语音、Agent 或数据清洗实习，但项目业务小、指标弱、工程闭环不足，想用于面试大厂实习。

核心原则：不把小厂经历伪装成大厂复杂系统，而是把真实经历整理成“问题定义清楚、贡献边界清楚、实验/评估可信、bad case 充分、工程补强可落地”的项目叙事。

## 一、先判断这段实习到底是什么类型

不要一律写“算法实习”。先归类：

| 类型 | 真实内容 | 更适合包装成 |
| --- | --- | --- |
| 跑模型/调参 | 复现 baseline、训练模型、调参数 | 算法实验与误差分析 |
| 数据清洗 | 清理字段、标注、去重、格式统一 | 数据质量与算法数据闭环 |
| 调 API | 接入 LLM/语音/视觉 API | AI 应用工程化 |
| Prompt/Agent | prompt、工具调用、流程编排 | LLM Agent 应用工程 |
| 业务规则 | 阈值、规则、分类、审核 | 规则 + 模型混合决策 |
| 报表/分析 | SQL、看板、指标分析 | 数据分析支持业务决策 |
| 只参与边角 | 文档、测试、样例、联调 | 算法工程协作与质量保障 |

## 二、小厂业务不足怎么补

小厂项目常见不足：

- 数据量不大。
- 没有严谨 AB 实验。
- 没有完整线上链路。
- 模型可能只是 API 或开源模型。
- 指标口径粗糙。
- 业务场景不够复杂。

补强方式不是硬编“大规模”，而是补：

- 问题定义：为什么业务需要这个模型/工具。
- 数据闭环：数据从哪里来、怎么清洗、怎么标注、怎么验证。
- Baseline：原始方法是什么，新方案比什么好。
- Bad case：失败样例、错误类型、原因归因。
- 评估口径：离线指标、抽样验证、人工复核、质量报告。
- 工程闭环：日志、接口、批处理、部署、监控、回滚、人工兜底。
- 可扩展设计：如果去大厂场景，数据量/并发/模型成本变大，怎么演进。

## 三、真实性边界

必须分清：

- 亲手做过：可以写“负责/实现/设计/优化”。
- 参与协作：写“参与/协助/对接/支持”。
- 了解但非主责：面试可提，不要放主 bullet。
- 可以补做：写进提升计划，做完再写成完成态。
- 不能写：无证据的线上指标、大规模、主导、核心算法、模型训练。

常见越界：

- “调用大模型 API”写成“训练大模型”。
- “清洗几千条数据”写成“海量数据治理”。
- “内部 demo”写成“生产系统上线”。
- “调参实验”写成“主导算法架构优化”。
- “准确率有变化但无口径”写成“提升 30%”。

## 四、算法实习简历漏洞清单

检查当前项目是否缺这些：

1. 业务背景：模型解决哪个业务决策问题？
2. 输入输出：输入特征/数据是什么，输出给谁用？
3. 数据规模：样本量、字段、标签、时间跨度，真实写，不夸大。
4. Baseline：原方法或原模型是什么？
5. 指标：Accuracy/F1/AUC/Recall/NDCG/WER/CER/延迟/成本，口径是什么？
6. 数据划分：训练/验证/测试怎么分，有没有泄漏？
7. Bad case：失败样例有哪些规律？
8. 个人贡献：你做的是数据、模型、评估、工程、联调还是文档？
9. 工程闭环：有没有脚本、接口、日志、配置、部署、测试、复现文档？
10. 业务结果：没有线上指标时，有没有抽样验证、人工复核或质量报告？

## 五、可真实补做的增强点

### 半天能补

- 把项目整理成 2-3 分钟叙事：背景、目标、职责、方案、结果、局限。
- 整理 10 条 bad case，并按错误类型分类。
- 补数据说明：字段、样本量、标签来源、清洗规则。
- 补 README：运行命令、输入输出、关键结果截图。

### 1 天能补

- 补 baseline 对比表：原方法 vs 改进方法。
- 补错误分析：混淆矩阵、bad case 分类、典型样例。
- 补指标口径说明：数据划分、随机种子、评估脚本。
- 补日志/配置：模型参数、数据版本、运行耗时。

### 3 天能补

- 做消融实验：去掉某类特征/规则/模块，看指标变化。
- 做小型人工评估集：20-100 条样例，标注期望输出和错误类型。
- 补一个可演示 API 或 demo 页面。
- 补单测或 smoke test，证明流程可复现。

### 1 周能补

- 把实验流程 pipeline 化：数据处理、训练/调用、评估、报告自动生成。
- 增加模型/规则版本管理。
- 增加监控思路：数据漂移、错误率、延迟、成本。
- 设计大厂规模演进方案：离线训练、在线推理、缓存、异步、AB、灰度。

## 七、大厂高频追问

1. 这个项目的算法难点在哪里？是不是只是调包/调 API？
2. 数据从哪里来？标签怎么来的？有没有噪声？
3. 数据量多大？为什么这个规模也能说明问题？
4. baseline 是什么？为什么选它？
5. 指标怎么计算？有没有数据泄漏？
6. 你说提升了，和什么对比？是否显著？
7. Bad case 有哪些？你怎么归因？
8. 如果上线，延迟、成本、稳定性怎么考虑？
9. 如果数据量扩大 10 倍，流程怎么改？
10. 你的个人贡献和同事/开源代码的边界是什么？
11. 为什么这段小厂经历能证明你适合大厂？
12. 如果给你一周重做，你会补什么？

## 八、防线回答

### Q：你这个是不是只是跑了一个开源模型？

A：项目确实基于开源模型/现有 API，我没有把它包装成底层模型创新。我的工作重点在真实业务数据接入、数据清洗、评估口径、错误样例分析和工程化流程。相比只跑 demo，我补了输入输出定义、baseline 对比、bad case 分类和后续上线风险分析。

### Q：小厂数据量这么小，有什么价值？

A：数据规模不大，所以我不会强调“大规模训练”。这段经历的价值在于我完整经历了从业务问题到数据处理、模型/规则验证、错误分析和迭代建议的闭环。面向更大规模场景，我会把数据处理 pipeline 化，引入分层评估、版本管理和线上监控。

### Q：没有线上指标，怎么证明有效？

A：目前没有严格线上 AB，所以我不会写线上提升。可用证据是离线评估、抽样人工复核、质量报告和 bad case 对比。如果继续推进，我会补固定评估集、灰度方案和线上反馈指标。

### Q：你的贡献是不是只是数据清洗？

A：如果事实如此，要承认边界。但数据清洗不是简单整理表格，我负责的是把原始业务数据变成可训练/可评估的数据：字段标准化、缺失和重复处理、异常样例导出、质量报告和错误归因，这些直接影响后续模型效果和实验可信度。

## 十、八股穿插训练

大厂面试不会只听项目故事。讲到项目中的一个点，就可能切到基础题和场景题。

优先读取：

- `algorithm-depth-question-bank.md`：算法实习深挖题库。
- `scenario-bagua-drills.md`：项目如何转成八股和场景题。

### 面试训练顺序

1. 先让用户讲 2 分钟项目。
2. 从项目里抓一个点追问，例如数据划分、指标、baseline、bad case。
3. 转成八股，例如 AUC/F1、过拟合、特征工程、缓存、接口、数据库。
4. 转成场景题，例如线上效果下降、延迟变高、上游字段变更、模型幻觉。
5. 最后回到简历：这部分能不能写，有没有证据，是否需要补做。

### 小厂算法实习最常见转场

| 用户项目点 | 面试官转场 | 必备回答 |
| --- | --- | --- |
| 数据清洗 | 缺失值/异常值/重复样本怎么处理 | 规则、样例、质量报告、对模型影响 |
| 模型训练 | 过拟合、欠拟合、正则化、交叉验证 | 现象、定位、解决方法 |
| 指标提升 | Accuracy/F1/AUC/Recall 区别 | 指标口径、业务目标、阈值 |
| 推荐/搜索 | 召回/排序/NDCG/冷启动 | 链路、指标、场景 |
| LLM/Agent | 幻觉、工具调用失败、结构化输出 | 校验、日志、人工复核 |
| API/demo | 接口超时、重试、幂等、日志 | trace、timeout、fallback |

### 输出要求

当用户说“模拟面试”时，不要只问开放题。按下面格式：

```text
第 1 题：项目追问
第 2 题：算法基础
第 3 题：工程场景
第 4 题：八股概念
第 5 题：简历防线
```

用户回答后给：

- 漏洞。
- 更好的回答。
- 能否写进简历。
- 需要补的证据。
